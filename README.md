# Balancing Robot

## Introduction
This is an ongoing personal project started on 02/08/2026. Up to 17/09/2026, the budget was controlled to within £60. The aim of this project was to build a steady balancing robot in the hopes of learning about PID control. 


## Hardware
Both the PCB and robot frame were designed by myself with PCB manufactured by JLCPCB and the frame 3D printed at home. The bottom layer and motor brackets have to withstand the most vibration so carbon fibre PETG was chosen for its rigidity. For the remaining parts of the frame, PLA was chosen as it was easier to print and there was no special requirements for material strength. 

## Software
The development was divided into several stages:
|Stage|Purpose|
|-----|-------|
|0| Confirm the clock ticks are generated correctly|
|1| Confirm the MPU6050 is connected to I2C of BluePill and can read from both the gyroscope and accelerometer with pitch angle fused correctly|
|2| Confirm the BluePill can receive data from MPU6050 via I2C and send messages to laptop through UART by HC-05|
|3| Confirm BluePill can receive commands from laptop via bluetooth communication by checking motors respond to commands|
|4| Adjust PID to achieve preliminary balance (robot should be able to balance on its own at this stage)|

## MATLAB simulation
Regarding the note I made, I could not get the robot to balance despite continued effort in tuning PID. Therefore, I hypothesised it could be the result of insufficient torque from my 500rpm motors. To test the hypothesis, I simulated the robot in MATLAB, but the results showed there is theoretically enough torque to support balancing.

Hence, to reduce development time, LQR algorithm was chosen with a model tested and simulated in MATLAB. I measured the period of oscillation in a pendulum test to get inertia, the height from COM to wheel axis and CPR of encoder as well as the mass and wheel radius. The MATLAB simulation files were generated by Claude as I was new to MATLAB.

## Current Result
The maximum time of robot staying upright currently is 40s with the code attached in the folder. Further adjustments are being made to reduce the oscillation, but overall, the goal of this project can be considered met for now.
